## 사람 결정이 필요한 것

에이전트는 여기 적힌 일을 스스로 하지 않는다. 일하다가 새로 생기면 아래에 날짜와 함께 적는다.

- 운영 주체·IP (G0). 배포 계정과 처리방침 명의가 여기에 달려 있다.
- 배포 (Vercel 프로젝트 만들기, 도메인).
- 원격 저장소 만들기와 공개 여부, 라이선스.
- `docs/cli-requests.md` 를 CLI 개발 쪽에 전달하기.
- 처분 사례·과징금 같은 법 관련 사실을 화면에 싣기 (출처 확인).
- 팩 작성자 메모(rationale)를 화면에 실을지. `kr.ai-basic-act.31-1` 의 메모에 과태료 액수와 조문 번호가 들어 있어
  지금은 싣지 않는다(2026-10-06).
  - 화면에는 그리지 않지만 배포물에는 실려 나간다(2026-10-07 에 빌드해 확인. 2번을 하기 전의 커밋 `12ec3c5` 를
    빌드해도 같다). `data/pack-meta.json` 을 `src/lib/pack/index.ts` 가 통째로 불러오고 그것을 브라우저에서 도는 부품이
    쓰기 때문에, `/view` 와 `/demo` 가 받는 `out/_next/static/chunks/` 의 JS 한 덩이에 다섯 정책의 메모와 그 액수 문장이
    들어 있다. `tests/commitments.test.ts` 는 소스의 문구와 `.rationale` 접근만 봐서 잡지 못한다. 배포 전에 정한다:
    브라우저로 가는 팩 메타데이터에서 메모를 뺄지(브라우저용 사본을 따로 두는 등), `out/` 의 파일을 보는 시험을 둘지.
- 브라우저 저장소(localStorage 등)를 어디까지 쓸지. 테마 선택 기억에 필요하다. 정해질 때까지 쓰지 않고, 연 결과는
  메모리에만 둔다(2026-10-06).
- 판정자를 켠 실제 수집본을 만들지. 판정자를 켜면 검사 대상 코드가 외부 API 로 나간다. 합성 코드라도 사람이 정한다.
  지금은 손으로 만든 자료(`tests/fixtures/judge-on.*.json`)로 화면을 시험한다(2026-10-06).
- CLI 저장소에 커밋되지 않은 변경이 있을 때(`MANIFEST.json` 의 `dirty: true`) 수집본을 받아들일지. 기본은 커밋하지 않는다.
- 개발 도구 텔레메트리(Next.js)를 끌지. 끄려면 `npx next telemetry disable` (개인 설정이 바뀐다).
- `npm audit` 가 알린 5건(2026-10-06). 모두 `eslint-config-next` 가 끌어오는 `braces` 한 건에서 나온다. 린트 도구라
  배포물(`out/`)에는 들어가지 않는다. `npm audit fix --force` 는 `eslint-config-next` 를 옛 판으로 내리므로 쓰지 않는다.
  상위 패키지가 고쳐지면 올린다.
- 판정자 없이 검사한 결과에서 "고치는 법"이 거의 비어 보이는 것을 어떻게 할지. 팩의 고치는 법은 주로 AI 대안에 적혀
  있는데, 묻지 않은 AI 대안은 결과의 `unsatisfied_alternatives` 에 실리지 않는다(`docs/cli-requests.md` 의 "팩 쪽에 전할
  관찰", R8). 팩 메타데이터에서 대안 id 로 찾아 보일 수는 있지만, 판정하지 않은 대안의 글을 확인되지 않은 대안처럼
  보이게 된다. 지금은 끌어오지 않고 "실려 있지 않습니다"라고 적는다(2026-10-06).
