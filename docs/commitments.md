# 지켜야 할 약속

멘토에게 공유한 방향 확정안(2026-09-28)과 확장 구상(2026-09-30)에서 정한 것이다. 이 문서의 내용을 바꾸는 것은
오너(육승현)의 결정이다. 기계로 볼 수 있는 것은 `tests/commitments.test.ts` 와 `tests/render.test.tsx` 가 본다.
시험은 흔한 실수를 잡는 그물이다. 시험이 통과해도 이 문서와 어긋나면 어긋난 것이다.

## 1. 말

| 쓰는 말 | 쓰지 않는 말 | 이유 |
|---|---|---|
| 미충족 신호(검토 필요) | 법을 어겼다고 단정하는 말 | 도구는 검토할 지점을 알릴 뿐이고 판단은 사람이 한다 |
| 충족 근거 발견 | 적법하다·문제없다고 단정하는 말 | 근거를 찾았다는 사실만 말한다 |
| 판단 보류(모름) | | 약한 근거뿐이거나 다 읽지 못했다 |
| 검토 필요 · AI 확인 전 | "판단 보류"로 뭉뚱그리기 | AI 대안은 쓸 수 있는 답이 없으면 판정에 넣지 않으므로 정적 판정(검토 필요)이 그대로 남는다. 판정자가 꺼진 경우, 답하지 못한 경우, 답을 쓸 수 없었던 경우(인용 불인정 등)가 모두 여기에 든다 |
| 알 수 없음 | "발견 없음"으로 뭉뚱그리기 | 다른 판의 팩으로 만든 결과에서는 그 팩에 이 정책이 있었는지 모른다 |
| 적용 신호 없음 | "해당 없음"으로 단정 | 코드 신호를 못 찾았다는 뜻이다 |
| JS/TS 코드(누가 썼든) | 특정 도구가 만든 코드용이라는 표현 | 코드를 누가 썼는지는 보지 않는다 |
| 인공지능기본법 제31조 제1항 / 제2항 | 가지조문처럼 읽히는 표기 | 제1항이 사전 고지, 제2항이 결과물 표시다 |

- 모든 화면에 "법률 자문이 아닙니다"가 보여야 한다(`SITE.disclaimer`, 바닥글).
- 발견이 0이면 "법적 문제가 없다는 뜻이 아니다"를 함께 보인다(`SITE.zeroIsNotClearance`).
- 점수, 등급, 순위, 비율, 배지를 만들지 않는다. 사람이 볼 곳의 개수만 센다.
- 과징금·과태료 예상액, "걸릴 확률", 변호사 연결을 두지 않는다(변호사법 쟁점).
- 예시 결과에는 "합성 예시"라고 밝힌다. 실제 남의 저장소 결과를 예시로 쓰지 않는다.
- 처분 사례, 과징금·과태료 액수를 화면에 싣지 않는다. 팩 작성자 메모(rationale)도 싣지 않는다(사람 결정 전까지).

### CLI 가 이미 약속한 것 (웹도 따른다)

CLI 의 README 가 사용자에게 약속한 것이다. 웹이 같은 결과를 보여 주면서 어기면 안 된다.

- **판정자를 켜면 코드가 밖으로 나간다는 것을 알린다.** 판정자를 켜 보라고 권하는 자리마다 "판정 대상 코드가 외부 API 로
  나간다"를 함께 적는다. 판정자가 꺼져 있었을 때만 권한다.
- **AI 가 푼 것을 숨기지 않는다.** AI 의 '예'로 풀린 경고(`run.ai_cleared`)와 적용 질문의 '아니오'로 빠진 판정
  (`run.ai_dismissed`)을 화면에 보인다. 인용이 코드에 있는지만 확인된 것이라 사람이 봐야 한다.
- **다 보지 못한 것을 숨기지 않는다.** 검사하지 않은 파일, 읽지 못한 파일, 엔진이 끝내지 못한 파일을 보인다.

## 2. 층마다 다른 약속

### 1층 (지금): 서버 없음

- 정적 사이트다. 서버 실행, 저장, 로그인, 개인정보 수집이 없다.
- `/view` 에서 연 파일은 브라우저 안에서만 읽는다. 어디로도 보내지 않는다.
- 분석 도구·광고·외부 글꼴 같은 제3자 요청을 넣지 않는다. 쪽이 스스로 밖으로 내보내는 요청이 없다.
- 브라우저 저장소(localStorage 등)는 어디까지 쓸지 정하지 않았다. 정해질 때까지 쓰지 않고, 연 결과는 메모리에만 둔다.

### 2층 (관문 G2 뒤, 초대제 공개 저장소 검사): 코드를 저장하지 않는다

- GitHub 로그인은 신원 확인만 한다. 저장소 권한을 요청하지 않고 이메일을 받지 않는다.
- 검사는 격리된 일회용 환경에서 하고, 코드를 받은 뒤 네트워크를 끊고, 끝나면 환경을 파기한다.
- 저장하는 것은 규칙·조문·경로·줄·판정·지문뿐이다. 코드, 코드 조각, 받은 압축 파일, AI 가 인용한 줄, 토큰은 저장하지 않는다.
- 화면의 코드 줄은 사용자 브라우저가 GitHub 에서 직접 받는다(커밋을 고정한 permalink).
- 결과는 요청한 사람만 본다. 남의 저장소 결과를 누구나 볼 수 있게 두지 않는다.
- 서버에서 AI 판정자를 돌리지 않는다(`--judge none`).

### 3층 (학기 뒤): 비공개 저장소

- 검사는 사용자 쪽(자기 GitHub Actions)에서 돌고, 우리는 코드 없는 결과만 받는다.
- 서버 AI 는 저장소별 동의, 개인정보보호법 제26조 위탁·재위탁 동의가 갖춰진 뒤에만 한다.

## 3. 엔진과 라이선스

- Semgrep CE(LGPL-2.1)는 PyPI 의존성으로만 쓴다. 바이너리나 컨테이너 이미지에 넣어 배포하지 않는다.
- Semgrep 공식 규칙(Registry)은 쓰지 않는다. 규칙 라이선스가 재배포와 서비스 제공을 금지한다.
- 이름·로고·도메인에 Semgrep 을 쓰지 않는다. "Semgrep CE 위에서 동작"이라는 사실만 적는다.
- 유료 호스팅 전에 Semgrep 에 제휴 문의를 한다.
- 이 저장소의 라이선스는 아직 정하지 않았다(비공개 또는 FSL 후보). 공개 전에 오너가 정한다.

## 4. 결정되지 않은 것 (사람 결정)

- 운영 주체와 IP (학생 개인 / 플리트소프트 / 그 밖). 처리방침·약관·배포 계정의 명의가 여기에 달려 있다.
- 브라우저 저장소를 어디까지 쓸지(테마 같은 화면 설정만 / 전혀 안 씀).
- 팩 작성자 메모(rationale)를 화면에 실을지.
- 공개 저장소의 코드 줄을 브라우저가 GitHub 에서 직접 받는 것을 1층에서도 허용할지.
- 공개 여부와 라이선스.
- 이름. CLI 이름(policypack)이 바뀌면 `src/lib/site.ts` 를 고친다.
