# CLI 에 보내는 요청

웹이 CLI(`../Plitsoft-SDP`) 출력에 바라는 것이다. 웹은 CLI 를 고치지 않는다. 이 문서를 CLI 개발 쪽에 전달하는 것은
사람의 일이다. 상태는 2026-10-06, CLI 커밋 `8ae72d8`(0.3.0.dev0) 기준이다.

요청마다 "지금 어떻게 되어 있는지"는 `contract/cli-current/` 의 실제 출력에서 확인한 것이다.

## 동결 전에 필요한 것

| # | 요청 | 지금 | 없으면 웹에서 생기는 일 | 상태 |
|---|---|---|---|---|
| R1 | 정책별 요약: 팩의 모든 정책마다 판정 단위 수, 검토 필요·판단 보류·충족 개수, 충족 근거 위치(파일·줄·규칙·대안 id) | 정적 조건으로 충족된 단위는 `run.units` 개수에만 들어가고 어디에도 나오지 않는다. `kids-signup.fixed` 는 `units: 1`, `findings: []`. AI 가 푼 단위만 `run.ai_cleared` 에 나온다 | "충족 근거 발견"과 "적용 신호 없음"을 구분하지 못해 둘 다 "발견 없음"으로 보인다. 빈 결과 화면에 무엇을 확인했는지 적을 수 없다 | 미반영 |
| R2 | 결과 JSON 에 `schema_version`, 그리고 출력 JSON Schema 공개 | `tool.version` 뿐이다 | 출력 모양이 바뀌어도 웹이 알 수 없어 조용히 틀리게 보인다 | 미반영 |
| R3 | 정책 단위 지문: 지문에 `pack.yaml` 전체 해시 대신 그 정책의 내용만 넣기 | 팩을 한 글자만 고쳐도 모든 지문이 바뀐다 | 두 결과를 비교해 "새로 생긴 신호"를 가릴 수 없다 | 미반영 |
| R4 | 코드가 한 줄도 없는 출력 방식 (AI 가 인용한 줄, AI 원문이 든 판정 경로 줄, 엔진 오류 원문 제외) | 판정자를 켠 결과에는 인용한 코드 줄이 실린다 | 2층에서 "코드를 저장하지 않는다"를 지키려면 웹이 필드를 골라 지워야 하고, 새 필드가 생기면 샌다 | 미반영 |
| R5 | 팩 메타데이터 JSON 내보내기: 정책 id·제목·조문과 원문·해시·시행일·재검토 기한·대안별 메시지·질문·고치는 법. 가능하면 적용 조건과 대안을 사람이 읽는 말로 푼 설명, 알려진 한계도 | 명령이 없다. 적용 조건의 설명과 한계는 팩에서 YAML 주석과 자유 문장으로만 있다 | 웹이 `scripts/export-pack-meta.mjs` 로 팩 문법을 직접 읽는다. 문법이 바뀌면 깨진다 | 미반영 (임시 스크립트로 대체 중) |

웹의 요청안은 `contract/schema/report.v1-draft.schema.json` 에 스키마로 적어 두었다. 필드 이름과 `schema_version`
값은 CLI 쪽이 정하는 대로 따른다.

## 그다음에 필요한 것

| # | 요청 | 왜 |
|---|---|---|
| R6 | 같은 정책이 여러 파일에서 반복될 때 정책당 위치 목록과 대표 위치 | 지금은 웹이 묶는다. CLI 의 글 출력과 SARIF 도 같은 문제를 가진다 |
| R7 | 실행 정보에 커밋 SHA, 원격 주소, 검사한 일시 | 코드 줄로 가는 고정 링크(permalink), 결과 캐시, 검사 기록의 날짜에 쓴다 |
| R8 | 판정 경로를 구조로: 조건 id·값·이유 코드. 대안 전부를 값과 함께 | 지금은 `decision_path` 가 문장이라 웹이 그대로 보여 주기만 한다. `unsatisfied_alternatives` 에는 거짓인 대안만 실린다. 판정에 넣지 않은 AI 대안(묻지 않음·답 없음·쓸 수 없는 답)과 참이지만 약해서 풀지 못한 대안은 목록에 없어 "대안 체크리스트"를 완성할 수 없다 |
| R9 | 적용 범위 선언(예: 국내 이용자 대상 여부)을 입력으로 받아 결과에 기록 | 국내 이용자가 없는 서비스의 결과를 오해 없이 보이기 위해 |
| R10 | 검사가 길어질 때 기계가 읽는 진행 상황과 파일 수·시간 상한 | 2층의 진행 표시와 정직한 중단 |
| R11 | SARIF 의 `invocations[0].properties` 에 판정 단위 수와 검사한 파일 수 | 지금 SARIF 에는 둘이 없어서 SARIF 를 열면 JSON 과 같은 화면을 만들 수 없다 |
| R12 | 실행 정보에 팩 id 와 제목 | 지금은 `pack_digest` 뿐이라 같은 팩의 다른 판인지 다른 팩인지 웹이 구분하지 못한다 |

팩을 쓰는 쪽에서 확인하면 된다.

## 새 요청을 적는 법

일하다가 CLI 출력에 없는 것이 필요해지면 화면에서 꾸며 내지 말고 여기에 적는다.

- 무엇이 필요한지, 어느 화면에서 왜 필요한지
- 지금 출력에서 확인한 사실 (`contract/cli-current/` 의 어느 파일, 어느 필드)
- 없을 때 웹이 어떻게 보이는지
